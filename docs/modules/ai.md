# AI Module

The AI module handles **machine-global AI coding agent setup** through one generic mechanism: the AI artifacts - skills, mods, rules, prompts and agents - kept in the repository under `AI/<Kind>/<source>/<item>`, vendored from upstream repositories and linked into the AI apps a machine uses (Claude Code, Codex, Gemini CLI, Copilot, or any app a fork defines), on Windows and in WSL; plus Claude Code plugin marketplace registration. Both are opt-in (`BootstrapConfig.Steps.AiArtifacts`, `BootstrapConfig.Steps.AiMarketplaces`), and the base harness catalogue is inactive until `AiArtifacts.Deploy` names a harness - a vanilla bootstrap links nothing and registers no marketplaces. Design pages: [AI Artifacts](../ai/artifacts.md), with the kind specifics on [CoreAiRules](../ai/coreairules.md), [AI Skills](../ai/skills.md) and [AI Mods](../ai/mods.md).

The skills, mods and rules commands of 1.5 (`Deploy-AiSkills`, `Deploy-AiMods`, `Deploy-CoreAiRules`, `Update-AiSkills`, `Update-AiMods`, `List-Skills`) are deprecated since 1.6.0 and removed in 2.0.0: each warns once per session and forwards to its replacement. See [Migrating from 1.5](../ai/artifacts.md#migrating-from-15).

## [Deploy-AiArtifacts](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Deploy-AiArtifacts.ps1)

- **Description:** Links the repository's AI artifacts into the AI apps this machine deploys into, on Windows and in WSL. The apps are the `AiHarnesses` entries `AiArtifacts.Deploy` names for the machine type; the items are every `<Root>\<Kind>\<source>\<item>` of the sources read (`own` first, then `winux`, `example` and the vendored sources in name order; the first wins an item name two carry, with a warning), minus `AiArtifacts.Exclude`. [Get-AiArtifactPlan](#get-aiartifactplan) joins the two and this function carries the plan out: an `Each` destination gets one symbolic link per item (the item folder, or the first file of the destination's `Files` the item has, named `<item>` plus its extension), a `Copy` destination a copy that is replaced when it differs, a `File` destination one link to the item `AiArtifacts.Use` names for the kind (the rules linked as `~\.claude\CLAUDE.md`, `~\.codex\AGENTS.md`, ...). A destination two apps name is filled once; one no item goes to is never created. A folder destination that is a link into the repository is replaced by a real folder; one that links elsewhere, or a file in its place, is skipped. Links go through [New-WindowsSymbolicLink](system.md#new-windowssymboliclink), which copies a real item in the way into `Backups\Windows\SymbolicLinks\AiArtifacts.<kind>.<item>` first; only dangling links into the artifacts root are pruned. Hooks: `claude-plugin-dirs` sets `env.CLAUDE_CODE_PLUGIN_DIRS` of `~\.claude\settings.json` to the links (`;`-separated) followed by every entry added by hand ([Resolve-AiModsPluginDirs](#resolve-aimodsplugindirs), [Set-ClaudeSettingsEnv](#set-claudesettingsenv)) and validates them with [Test-AiModsCli](#test-aimodscli) (a missing or rejecting CLI only warns); `managed-settings` makes the WSL twin as root. A harness with `WSL = $true` deploys every destination with a WSL twin (a `{User}` path mapped onto `/home/<DefaultWSLUsername>`, or the destination's `WSLPath`) inside the default distribution too, one `wsl -e sh <script>` call per destination, with the same backup, replace and prune rules; the WSL settings file is updated through the `\\wsl.localhost\<distro>` share with `:` as the separator. `-WhatIf` reports `MISSING`, `WRONG`, `DIFFERS` and `STALE` entries and changes nothing. Each deprecated key [Resolve-AiArtifactsConfig](#resolve-aiartifactsconfig) maps is reported as a warning. Requires administrator privileges unless `-WhatIf`. Called by Bootstrap when the opt-in `BootstrapConfig.Steps.AiArtifacts` toggle is enabled (OFF by default); the deprecated wrappers `Deploy-AiSkills`, `Deploy-AiMods` and `Deploy-CoreAiRules` call it with one kind. Idempotent.
- **Parameters:** -Kind (Skills, Mods, Rules, Prompts, Agents), -WhatIf
- **Usage:** `Deploy-AiArtifacts`, `Deploy-AiArtifacts -Kind Rules -WhatIf`, `Deploy-AiArtifacts Skills, Mods`

**See also:** [Update-AiArtifacts](#update-aiartifacts), [List-AiArtifacts](#list-aiartifacts), [AI Artifacts](../ai/artifacts.md)

## [Deploy-AiMarketplaces](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Deploy-AiMarketplaces.ps1)

- **Description:** Registers every Claude Code plugin marketplace under `AiMarketplaces.Marketplaces` in the user's `~\.claude\settings.json` (`extraKnownMarketplaces.<name>`, the GitHub repository as the source, every other setting kept, written through [Set-ClaudeSettingsKey](#set-claudesettingskey)), writes the variables each marketplace's `Env` names into the `env` block of the same file through [Set-ClaudeSettingsEnv](#set-claudesettingsenv) (as strings, every other variable kept, marketplaces in name order so the last wins a clash; an invalid name or a non-hashtable `Env` is reported and skipped; the place for a switch a plugin cannot set itself, such as `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` on Claude Code 2.1.286), writes the plugins' options from `AiMarketplaces.PluginConfigs` beneath `pluginConfigs.<plugin>@<marketplace>` (the key of an installed plugin; a name no configured marketplace lists is written as given) one child key at a time, then, with the `claude` CLI on PATH, adds every marketplace `claude plugin marketplace list --json` does not show with `claude plugin marketplace add` and installs every listed plugin as `<plugin>@<marketplace>` through `claude plugin install` unless `claude plugin list --json` already shows it. A missing CLI only warns - the settings are deployed regardless. Inside WSL (`DefaultWSLDistribution` and `DefaultWSLUsername` set) the marketplaces, variables and options are written to the WSL user's settings file `/home/<DefaultWSLUsername>/.claude/settings.json` too (share reachable), and the add and install steps run again against the Claude Code CLI inside WSL through `wsl -d <distro> -u <user>` and a login shell; a `claude` WSL resolves under `/mnt/` (the Windows CLI through interop) or none at all only warns. Warns, without changing anything, about a folder in `env.CLAUDE_CODE_PLUGIN_DIRS` of either settings file that holds a plugin a configured marketplace installs. Idempotent. Called by Bootstrap when the opt-in `BootstrapConfig.Steps.AiMarketplaces` toggle is enabled (OFF by default).
- **Parameters:** -Command, -WslCommand
- **Usage:** `Deploy-AiMarketplaces`

Marketplaces are not an artifact kind: their plugins install through Claude Code's own CLI. A plugin loaded from a folder as a mod by [Deploy-AiArtifacts](#deploy-aiartifacts) and installed from a marketplace would run twice: give each plugin one loading path. A folder in `env.CLAUDE_CODE_PLUGIN_DIRS` that holds a plugin a configured marketplace installs is reported as a warning and left in place: Claude Code would load two copies, and the folder copy reads its options from `pluginConfigs.<plugin>`, not `<plugin>@<marketplace>`, so it draws with its defaults. Load a development clone with `claude --plugin-dir <clone>` for one session instead of listing it in the settings. Design: [AI Mods - Marketplaces](../ai/mods.md#marketplaces).

## [Get-AiArtifactPlan](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Get-AiArtifactPlan.ps1)

- **Description:** Builds the deployment plan that [Deploy-AiArtifacts](#deploy-aiartifacts) carries out and [List-AiArtifacts](#list-aiartifacts) `-ListDiscrepancies` checks, by joining the harness definitions of the resolved configuration with the roster of each kind ([Get-AiArtifactRoster](#get-aiartifactroster)). A destination two harnesses name is planned once, for the first (a second definition that differs in kind, placement or files is reported). `Each` and `Copy` destinations get one entry per item - the item folder when `Files` holds `.`, else the first file of the list the item has, named `<item>` plus that file's extension (`claude.md` as `<item>.md`, `copilot.agent.md` as `<item>.agent.md`); an item with none of them is left out. A `File` destination gets the item `AiArtifacts.Use` names for its kind, if it has one of the files. Returns `@{ Destinations; Warnings; Notes }`: each destination is `@{ Harness; Kind; Placement; Hooks; Path; WSLPath; Items }` and each item `@{ Kind; Name; Source; Target; WSLTarget }`; `Warnings` holds problems (an unknown harness, an incomplete destination, a duplicate item, a `Use` entry naming no item), `Notes` things left out on purpose. Writes nothing.
- **Parameters:** -Kind, -Config
- **Usage:** `Get-AiArtifactPlan`, `Get-AiArtifactPlan -Kind Rules`, `(Get-AiArtifactPlan).Destinations | ForEach-Object { "$($_.Path): $($_.Items.Count)" }`

## [Get-AiArtifactRoster](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Get-AiArtifactRoster.ps1)

- **Description:** Enumerates the AI artifacts of one kind under the artifacts root, flattened by item name - the single reading every AI artifact function shares, so what is listed is exactly what is deployed. Sources are read `own` first, then, in name order, `winux`, `example` and every `AiArtifacts.Sources` entry; any other source folder (Foundation's `foundation` in a repository that carries both halves) is not read. An item is a folder: a skill holds `SKILL.md`, a mod `.claude-plugin\plugin.json`, a rules, prompt or agent item at least one file not starting with a dot. `AiArtifacts.Exclude` applies (`kind/name` for every source, `kind/source/name` for one), names compare case-insensitively, and the first source wins a name two carry. Returns `@{ Root; Kind; Items; Duplicates }`: `Items` an ordered map of name to `@{ Name; Path; Source; Kind }`, `Duplicates` the losing entries with the source they lost to. A missing root or kind folder yields an empty roster.
- **Parameters:** -Kind, -Config
- **Usage:** `(Get-AiArtifactRoster -Kind Skills).Items.Count`, `(Get-AiArtifactRoster -Kind Rules).Items['CoreAiRules'].Source`

## [List-AiArtifacts](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/List-AiArtifacts.ps1)

- **Description:** The catalog counterpart to [Deploy-AiArtifacts](#deploy-aiartifacts): lists the AI artifacts the repository carries, grouped by kind and then source, each with the `description:` of its frontmatter (`SKILL.md`, the first Markdown file of a rules, prompt or agent item) or of a mod's `plugin.json`. The roster comes from disk exactly as `Deploy-AiArtifacts` reads it ([Get-AiArtifactRoster](#get-aiartifactroster): `own` first, `AiArtifacts.Exclude` applied), so a vendored refresh shows up at once. `-Kind` limits the kinds, `-Source` picks sources by number or name and `-Name` filters item names with wildcards, case-insensitively; an empty `-Source @()` or `-Name @()` opens a menu. `-ListDiscrepancies` compares the roster with what is deployed into the Windows destinations of the harnesses `AiArtifacts.Deploy` names ([Get-AiArtifactPlan](#get-aiartifactplan)), reporting an item that is not deployed, an entry that shadows one with a real file or points elsewhere, a dangling or orphaned link into the artifacts root, an item name two sources carry, and the plan's warnings; WSL twins are not read (re-run `Deploy-AiArtifacts` to reconcile them). `-Quiet` suppresses the all-clear banner. The catalog is drawn with the helpers `List-Functions` uses - a [Create-CenteredBorder](helper.md#create-centeredborder) header per kind and source, [Show-FunctionDetails](helper.md#show-functiondetails) per entry - and everything it emits on its own account goes through the Logging module.
- **Parameters:** -Kind, -Source, -Name, -ListDiscrepancies, -Quiet
- **Usage:** `List-AiArtifacts`, `List-AiArtifacts -Kind Skills -Source own`, `List-AiArtifacts -Name "*review*"`, `List-AiArtifacts -ListDiscrepancies`

## [Resolve-AiArtifactsConfig](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Resolve-AiArtifactsConfig.ps1)

- **Description:** Resolves the `AiArtifacts` and `AiHarnesses` sections into one hashtable every AI artifact function shares, for one machine type: `Root` (default `{RepoRoot}\AI`), `Sources` (name to `@{ Repository; Ref; Kinds; Exclude; SkipPaths }`, `Kinds` mapping each kind to its upstream folders, `Skills = @("skills")` when none is given), `Exclude` (lowercased, the entries scoped to this machine type), `Use` (kind to item name, per machine type), `Deploy` (the harnesses of the machine type's own `Deploy` key, else `Default`), `Harnesses` (each deployed `AiHarnesses` entry with its destinations expanded and filtered by their `Machine` scope, each with its `WSLPath` twin: the destination's own `WSLPath`, else the `{User}` path mapped onto `/home/<DefaultWSLUsername>`), `Unknown` (`Deploy` names with no `AiHarnesses` entry), `WSLUser` and `Legacy`. Deprecated keys are read and mapped, one `Legacy` message each: `AiSkills.Sources` and `AiMods.Sources` become sources with `Skills` or `Mods` = `Folders` (an `AiArtifacts.Sources` entry of the same name wins), an `AiSkills` or `AiMods` `Root` other than the default moves `Root` to its parent folder, a rules item a `PathTemplates.SymbolicLinks.AI` entry targets becomes `Use.Rules` when none is set, and when `Deploy` lists nothing but a deprecated step (`CoreAiRules`, `AiSkills`, `AiMods`) is on or a deprecated `Sources` key is set, `Deploy` is `claude-code`, `codex` and `gemini-cli`. Expands `{RepoRoot}`, `{User}` and `{AppData}` only; every key falls back to its default, so the base configuration resolves to a setup that deploys nothing.
- **Parameters:** -Configuration, -RepoRoot, -MachineType
- **Usage:** `(Resolve-AiArtifactsConfig).Deploy`, `(Resolve-AiArtifactsConfig -MachineType Work).Harnesses['claude-code'].Destinations`

## [Set-ClaudeSettingsEnv](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Set-ClaudeSettingsEnv.ps1)

- **Description:** Sets one variable in the `env` block of a Claude Code `settings.json` (default `~\.claude\settings.json`; a `\\wsl.localhost` path edits a WSL user's file) by reading the whole document, setting exactly that key and writing the whole document back, so every other top-level key, nested object and `env` variable survives. A missing file is created with only the key; a file without `env` gains one; an unchanged value writes nothing. Unparseable JSON, a non-object top level or a non-object `env` is logged as an error, left untouched, and returns `$false`. Writes UTF-8 without a BOM, two-space indented with LF line endings, and keeps date-like strings verbatim. Supports `-WhatIf`. Used by [Deploy-AiArtifacts](#deploy-aiartifacts) (the `claude-plugin-dirs` hook) and [Deploy-AiMarketplaces](#deploy-aimarketplaces).
- **Parameters:** -Name, -Value, -SettingsPath, -WhatIf
- **Usage:** `Set-ClaudeSettingsEnv -Name CLAUDE_CODE_PLUGIN_DIRS -Value "C:\Users\You\.claude\mods\my-mod"`, `Set-ClaudeSettingsEnv -Name CLAUDE_CODE_PLUGIN_DIRS -Value "" -WhatIf`

## [Set-ClaudeSettingsKey](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Set-ClaudeSettingsKey.ps1)

- **Description:** Sets one key, at any depth, of a Claude Code `settings.json` (default `~\.claude\settings.json`; a `\\wsl.localhost` path edits a WSL user's file) by its dotted path, e.g. `extraKnownMarketplaces.my-marketplace` or `pluginConfigs.my-plugin.options`: reads the whole document, sets exactly that key, creates the objects along the path, and writes the whole document back, so every other key survives. A hashtable or array value becomes the JSON it describes; a value already equal (as JSON) writes nothing; a missing file is created with only the path. Unparseable JSON, a non-object top level or a non-object value along the path is logged as an error, left untouched, and returns `$false`. Writes UTF-8 without a BOM, two-space indented with LF line endings, and keeps date-like strings verbatim. Supports `-WhatIf`. The generic sibling of [Set-ClaudeSettingsEnv](#set-claudesettingsenv); used by [Deploy-AiMarketplaces](#deploy-aimarketplaces).
- **Parameters:** -Path, -Value, -SettingsPath, -WhatIf
- **Usage:** `Set-ClaudeSettingsKey -Path "extraKnownMarketplaces.my-marketplace" -Value @{ source = @{ source = "github"; repo = "MyOrg/MyMarketplace" } }`, `Set-ClaudeSettingsKey -Path "pluginConfigs.my-plugin.options" -Value @{ theme = "light" } -WhatIf`

## [Test-AiModsCli](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Test-AiModsCli.ps1)

- **Description:** Checks that the Claude Code CLI resolves on PATH and runs `claude plugin validate <path>` on every given mod, returning `@{ Installed; Invalid }` - `Invalid` holds the mod paths whose validation exited non-zero or threw, and is empty when the CLI is missing (nothing could be checked). The CLI's validator is the practical gate for the mod API, since an older CLI rejects a mod it cannot load. The `claude-plugin-dirs` hook of [Deploy-AiArtifacts](#deploy-aiartifacts) only warns on the result.
- **Parameters:** -ModPath, -Command
- **Usage:** `Test-AiModsCli -ModPath "$env:USERPROFILE\.claude\mods\my-mod"`, `(Test-AiModsCli -ModPath $links).Invalid`

## [Update-AiArtifacts](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Update-AiArtifacts.ps1)

- **Description:** Vendors AI artifacts from the upstream repositories in `AiArtifacts.Sources` into `<Root>\<Kind>\<source>\`, pinned. Per source it resolves `Ref` to an exact commit through the GitHub API and downloads that commit's archive once, then, for every kind the entry names (`Skills`, `Mods`, `Rules`, `Prompts`, `Agents` = upstream folders, `.` for the repository root; no kind key: `Skills = @("skills")`), copies the items found: skills are the folders holding `SKILL.md` (the category level dropped), mods a folder holding `.claude-plugin\plugin.json` or each such subfolder (named by its `plugin.json` `name`), rules, prompts and agents every subfolder plus every top-level `NAME.md` (not `README`, `CHANGELOG` or `LICENSE`), which becomes item `NAME` holding it as `RULES.md`, `PROMPT.md` or `AGENT.md`. The entry's `Exclude` items are left out, and so are the top-level entries of an item listed in `SkipPaths` (default `.git`, `.github`, `tests`, `design`, `docs`). Writes `UPSTREAM.md` per kind folder (repository, commit, fetch time, folders, exclusions, skipped paths, item table; LF, the format Foundation writes and [Get-AiSkillManifest](#get-aiskillmanifest) reads) and the upstream license. Only items the previous manifest lists are replaced, so hand-made folders survive; a network failure leaves the vendored copy untouched. `-Check` compares each pinned commit with the upstream head and changes nothing. Private repositories work with a GitHub token (`GITHUB_TOKEN`, else `GH_TOKEN`, else `gh auth token`): both requests then authenticate and the archive comes from the API's zipball endpoint; the token goes only to `api.github.com` and is never logged. Deprecated `AiSkills.Sources` and `AiMods.Sources` entries are read as sources. Not a Bootstrap step: the vendored tree is committed, and [Deploy-AiArtifacts](#deploy-aiartifacts) links it. Called by the deprecated wrappers `Update-AiSkills` and `Update-AiMods`.
- **Parameters:** -Source, -Check
- **Usage:** `Update-AiArtifacts`, `Update-AiArtifacts -Source mattpocock`, `Update-AiArtifacts -Check`, `$env:GITHUB_TOKEN = "<token>"; Update-AiArtifacts -Source my-private-source`

**See also:** [Get-AiSkillManifest](#get-aiskillmanifest), [Get-AiSkillDescription](#get-aiskilldescription), [AI Artifacts - Vendoring](../ai/artifacts.md#vendoring)

## [Update-AiMods](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Update-AiMods.ps1)

- **Description:** Deprecated since 1.6.0, removed in 2.0.0. Warns once per session, then runs [Update-AiArtifacts](#update-aiartifacts) with `-Source` and `-Check` forwarded. `AiMods.Sources` entries are read as `AiArtifacts` sources until 2.0.0. Migration: move each `AiMods.Sources` entry to `AiArtifacts.Sources` with `Folders` renamed to `Mods` (`Exclude` and `SkipPaths` keep their names) and call `Update-AiArtifacts`.
- **Parameters:** -Source, -Check
- **Usage:** `Update-AiMods`, `Update-AiMods -Source my-mod`, `Update-AiMods -Check`
