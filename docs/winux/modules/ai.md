# AI Module

The AI module handles **machine-global AI coding agent setup** through one generic mechanism: the AI artifacts - skills, mods, rules, prompts and agents - kept in the repository under `AI/<Kind>/<source>/<item>`, vendored from upstream repositories and linked into the AI apps a machine uses (Claude Code, Codex, Gemini CLI, Copilot, or any app a fork defines), on Windows and in WSL; plus Claude Code plugin marketplace registration and the MCP servers of Claude Code and Codex. All three are opt-in (`BootstrapConfig.Steps.AiArtifacts`, `BootstrapConfig.Steps.AiMarketplaces`, `BootstrapConfig.Steps.AiMcpServers`), and the base harness catalogue is inactive until `AiArtifacts.Deploy` names a harness - a vanilla bootstrap links nothing, registers no marketplaces and adds no MCP servers. Per-machine AI profiles (`AiProfiles`, off by default) pick the rules, the Plan the managed settings pin, the apps, artifacts, MCP servers and marketplaces of each machine, and the repositories its agents may touch. Design pages: [AI Artifacts](../ai/artifacts.md), with the kind specifics on [CoreAiRules](../ai/coreairules.md), [AI Skills](../ai/skills.md) and [AI Mods](../ai/mods.md), [AI MCP Servers](../ai/mcp-servers.md) and [AI Profiles](../ai/profiles.md).

## [ConvertTo-AiManagedSettings](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/ConvertTo-AiManagedSettings.ps1)

- **Description:** Renders a rules item's `managed-settings.json` for one managed-settings folder and the `ai-profile.conf` the ownership guard reads next to it, reading and writing nothing. Every `{ManagedDir}` token becomes the folder with forward slashes; with an AI profile active, `forceLoginOrgUUID` is set from the profile's Plan (one UUID as a string, several as an array; a profile without a Plan leaves the template's value and reports it; one whose Plan is configured but unusable, an `OrgUuid` that is not a UUID, renders nothing, so the deployed copy keeps its pin) and the guard is appended to `hooks.UserPromptSubmit` and `hooks.PreToolUse` (matcher `*`) as `bash "<folder>/ai-ownership-guard.sh" <Event>`, then the repository policy hook to `hooks.PreToolUse` (matcher `*`) as `bash "<folder>/ai-repository-policy.sh"`. The settings come back as two-space indented JSON with LF line endings and a final newline, so the same input renders the same text and a deploy can compare it with the deployed copy. `ai-profile.conf` (profiles only) holds `profile`, `default-owner`, `unattended on|off`, one `plan <name> <uuid>` per Plan entry, `shared <pattern>`, `owns <profile> <pattern>` for every profile, and the active profile's `autonomous <pattern>` lines, then its repository policy: `default-policy <level>` (`branch` when unset), one `policy <level> <pattern>` per pattern, most trust first so the least trusting level wins where several match, and `merge-without-checks <pattern>`. Returns `@{ Settings; ProfileConf; Problems }`; an unparseable template leaves `Settings` empty. Used by [Deploy-AiManagedSettings](#deploy-aimanagedsettings) and [List-AiArtifacts](#list-aiartifacts) `-ListDiscrepancies`.
- **Parameters:** -Template, -ManagedDir, -AiProfile
- **Usage:** `ConvertTo-AiManagedSettings -Template (Get-Content -Raw "C:\Repo\AI\Rules\own\MyRules\managed-settings.json") -ManagedDir "C:\Program Files\ClaudeCode" -AiProfile (Resolve-AiProfile)`

## [Deploy-AiArtifacts](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Deploy-AiArtifacts.ps1)

- **Description:** Links the repository's AI artifacts into the AI apps this machine deploys into, on Windows and in WSL. The apps are the `AiHarnesses` entries `AiArtifacts.Deploy` names for the machine type (with an AI profile active, the profile's `Deploy`, and its `Rules` as the rules item; [Resolve-AiProfile](#resolve-aiprofile)); the items are those of the sources read, in precedence order `own`, the checkout sources, `winux`, `example`, the vendored sources, the manifest sources (the first wins an item name two carry, with a warning), minus `AiArtifacts.Exclude` and the profile's excludes. Before planning, the pinned refs of the manifest sources missing from the cache are cloned ([Sync-AiManifestCache](#sync-aimanifestcache); never under `-WhatIf`). [Get-AiArtifactPlan](#get-aiartifactplan) joins the two and this function carries the plan out: an `Each` destination gets one symbolic link per item (the item folder, or the first file of the destination's `Files` the item has, named `<item>` plus its extension), a `Copy` destination a copy that is replaced when it differs, a `File` destination one link to the item `AiArtifacts.Use` names for the kind (the rules linked as `~\.claude\CLAUDE.md`, `~\.codex\AGENTS.md`, ...). A destination two apps name is filled once; one no item goes to is never created. A folder destination that is a link into the repository is replaced by a real folder; one that links elsewhere, or a file in its place, is skipped. Links go through [New-WindowsSymbolicLink](system.md#new-windowssymboliclink), which copies a real item in the way into `Backups\Windows\SymbolicLinks\AiArtifacts.<kind>.<item>` first; a link in the way (a wrong one, or one whose target is gone) is simply replaced; only dangling links into the artifacts root, the manifest cache or a checkout source are pruned. Hooks: `claude-plugin-dirs` sets `env.CLAUDE_CODE_PLUGIN_DIRS` of `~\.claude\settings.json` to the links (`;`-separated) followed by every entry added by hand ([Resolve-AiModsPluginDirs](#resolve-aimodsplugindirs), [Set-ClaudeSettingsEnv](#set-claudesettingsenv)) and validates them with [Test-AiModsCli](#test-aimodscli) (a missing or rejecting CLI only warns); `managed-settings` hands the destination to [Deploy-AiManagedSettings](#deploy-aimanagedsettings), which writes an administrator-owned rendered copy (never a link) with the rules item's `hooks\`, and with a profile the ownership guard and `ai-profile.conf`, on Windows and as root in WSL; `git-exclude` (the repository-scoped destinations [Get-AiArtifactPlan](#get-aiartifactplan) plans for `repo:<name>` manifest rows) lists the links in that repository's `.git\info\exclude`. A harness with `WSL = $true` deploys every destination with a WSL twin (a `{User}` path mapped onto `/home/<DefaultWSLUsername>`, or the destination's `WSLPath`) inside the default distribution too, one `wsl -e sh <script>` call per destination, with the same backup, replace and prune rules; the WSL settings file is updated through the `\\wsl.localhost\<distro>` share with `:` as the separator. `-WhatIf` reports `MISSING`, `WRONG`, `DIFFERS` and `STALE` entries and changes nothing. Requires administrator privileges unless `-WhatIf`. Called by Bootstrap when the opt-in `BootstrapConfig.Steps.AiArtifacts` toggle is enabled (OFF by default). Idempotent.
- **Parameters:** -Kind (Skills, Mods, Rules, Prompts, Agents), -WhatIf
- **Usage:** `Deploy-AiArtifacts`, `Deploy-AiArtifacts -Kind Rules -WhatIf`, `Deploy-AiArtifacts Skills, Mods`

**See also:** [Update-AiArtifacts](#update-aiartifacts), [List-AiArtifacts](#list-aiartifacts), [AI Artifacts](../ai/artifacts.md)

## [Deploy-AiManagedSettings](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Deploy-AiManagedSettings.ps1)

- **Description:** Deploys the `managed-settings` destination of a harness (`C:\Program Files\ClaudeCode\managed-settings.json`, WSL `/etc/claude-code/`) as an administrator-owned copy, never a link, so nothing that can write the repository can loosen the policy. Into the managed folder it writes `managed-settings.json` rendered by [ConvertTo-AiManagedSettings](#convertto-aimanagedsettings), the rules item's `hooks\` folder file by file (scripts with LF line endings), and with an AI profile active the engine's `ai-ownership-guard.sh` and `ai-repository-policy.sh` (the repository's `AI\Hooks` folder; a missing one is warned about, the rest still deployed) and `ai-profile.conf`. A file is rewritten only when its rendered content differs; a link in the way (the earlier link-style deploy) is replaced; a real file that differs is first backed up through [Backup-RepositoryItem](helper.md#backup-repositoryitem) into `Backups\Windows\SymbolicLinks\AiArtifacts.rules.<item>.<file>`; other files in the folder are left alone. With `-Distribution`, the same files rendered for the WSL folder are staged in a temporary folder and copied in one `wsl -d <distro> -u root -e sh <script>` call (`root:root`, mode 644, each only when `cmp` finds it different, a differing real file backed up through its `/mnt` path first); the staging files are removed afterwards. `-WhatIf` reports `MISSING`, `WRONG` and `DIFFERS` files and changes nothing. Returns `@{ Deployed; Failures }`. Called by [Deploy-AiArtifacts](#deploy-aiartifacts), which holds the administrator rights.
- **Parameters:** -Destination, -AiProfile, -Distribution, -GuardPath, -PolicyHookPath, -BackupRepoRoot, -WhatIf
- **Usage:** `Deploy-AiManagedSettings -Destination $destination -AiProfile (Resolve-AiProfile) -WhatIf`

## [Deploy-AiMarketplaces](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Deploy-AiMarketplaces.ps1)

- **Description:** Registers every Claude Code plugin marketplace under `AiMarketplaces.Marketplaces` in the user's `~\.claude\settings.json` (`extraKnownMarketplaces.<name>`, the GitHub repository as the source, every other setting kept, written through [Set-ClaudeSettingsKey](#set-claudesettingskey)), writes the variables each marketplace's `Env` names into the `env` block of the same file through [Set-ClaudeSettingsEnv](#set-claudesettingsenv) (as strings, every other variable kept, marketplaces in name order so the last wins a clash; an invalid name or a non-hashtable `Env` is reported and skipped; the place for a switch a plugin cannot set itself, such as `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` on Claude Code 2.1.286), writes the plugins' options from `AiMarketplaces.PluginConfigs` beneath `pluginConfigs.<plugin>@<marketplace>` (the key of an installed plugin; a name no configured marketplace lists is written as given) one child key at a time, then, with the `claude` CLI on PATH, adds every marketplace `claude plugin marketplace list --json` does not show with `claude plugin marketplace add` and installs every listed plugin as `<plugin>@<marketplace>` through `claude plugin install` unless `claude plugin list --json` already shows it. A missing CLI only warns - the settings are deployed regardless. Inside WSL (`DefaultWSLDistribution` and `DefaultWSLUsername` set) the marketplaces, variables and options are written to the WSL user's settings file `/home/<DefaultWSLUsername>/.claude/settings.json` too (share reachable), and the add and install steps run again against the Claude Code CLI inside WSL through `wsl -d <distro> -u <user>` and a login shell; a `claude` WSL resolves under `/mnt/` (the Windows CLI through interop) or none at all only warns. Warns, without changing anything, about a folder in `env.CLAUDE_CODE_PLUGIN_DIRS` of either settings file that holds a plugin a configured marketplace installs. With an AI profile active ([Resolve-AiProfile](#resolve-aiprofile)), only the marketplaces its `Marketplaces` list names are deployed (left out: all; `@()`: none), and the `PluginConfigs` of a left-out marketplace's plugins are left out too; a marketplace is never removed. Idempotent. Called by Bootstrap when the opt-in `BootstrapConfig.Steps.AiMarketplaces` toggle is enabled (OFF by default).
- **Parameters:** -Command, -WslCommand
- **Usage:** `Deploy-AiMarketplaces`

Marketplaces are not an artifact kind: their plugins install through Claude Code's own CLI. A plugin loaded from a folder as a mod by [Deploy-AiArtifacts](#deploy-aiartifacts) and installed from a marketplace would run twice: give each plugin one loading path. A folder in `env.CLAUDE_CODE_PLUGIN_DIRS` that holds a plugin a configured marketplace installs is reported as a warning and left in place: Claude Code would load two copies, and the folder copy reads its options from `pluginConfigs.<plugin>`, not `<plugin>@<marketplace>`, so it draws with its defaults. Load a development clone with `claude --plugin-dir <clone>` for one session instead of listing it in the settings. Design: [AI Mods - Marketplaces](../ai/mods.md#marketplaces).

## [Deploy-AiMcpServers](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Deploy-AiMcpServers.ps1)

- **Description:** Adds every MCP server under `AiMcpServers.Servers` to the apps `AiMcpServers.Deploy` names for the machine type (`claude-code`, `codex`; any other name is warned about and skipped). A server is a `Url` (an HTTP server, or an SSE one with `Transport = "sse"`) with optional `Headers` and `BearerTokenEnvVar`, or a `Command` with optional `Args` and `Env` (a stdio server); `Machine` scopes it to some machine types through [Test-MachineTypeScope](bootstrap.md#test-machinetypescope), and an invalid entry is reported with every reason and skipped without skipping the rest. **Claude Code:** with the `claude` CLI on PATH, a server the `mcpServers` block of the user's `~\.claude.json` (`$env:CLAUDE_CONFIG_DIR\.claude.json` when set) does not carry is added at user scope with `claude mcp add --scope user`, one it carries with another definition is removed with `claude mcp remove --scope user` and added again, and one it carries as configured is left alone; the file is only read, the CLI writes it, and a missing CLI only warns. **Codex:** each server's `[mcp_servers.<name>]` table is written to `~\.codex\config.toml` (`$env:CODEX_HOME\config.toml` when set), replacing that table and its subtables in place or appending it, with every other line, comments included, and the file's line endings kept; the file is rewritten only when a table changed. Codex reads only stdio and streamable HTTP servers, so an `sse` server is skipped there with a warning. `BearerTokenEnvVar` keeps the secret out of the repository: Claude Code gets an `Authorization: Bearer ${VAR}` header, which it expands when it starts, and Codex `bearer_token_env_var`. With an AI profile active ([Resolve-AiProfile](#resolve-aiprofile)), only the servers its `McpServers` list names are registered (left out: all; `@()`: none). Every server it added, updated or found carried exactly as configured is recorded per app (`claude-code`, `codex`, `wsl:claude-code`, `wsl:codex`) in `%LOCALAPPDATA%\WinuX\ai-mcp-servers.state`, and a recorded server the profile no longer lists is removed (`claude mcp remove --scope user`, or its Codex table taken out, the file's other lines kept); a server the user added by hand, or one carried with another definition, is never removed. Inside WSL (`DefaultWSLDistribution` and `DefaultWSLUsername` set) the Codex tables are written to `/home/<DefaultWSLUsername>/.codex/config.toml` through the `\\wsl.localhost\<distro>` share (an unreachable share only warns), and the Claude Code steps run again against the Claude Code CLI inside WSL through `wsl -d <distro> -u <user>` and a login shell, comparing with that user's `~/.claude.json` read through WSL; a `claude` WSL resolves under `/mnt/` (the Windows CLI through interop) or none at all only warns. Idempotent. Called by Bootstrap when the opt-in `BootstrapConfig.Steps.AiMcpServers` toggle is enabled (OFF by default).
- **Parameters:** -Command, -WslCommand
- **Usage:** `Deploy-AiMcpServers`

MCP servers are not an artifact kind: each app keeps them in its own configuration file, so they are written there rather than linked. A server that signs in with OAuth needs the sign-in once per machine and app, `/mcp` in Claude Code and `codex mcp login <name>` in Codex, because the tokens stay in the machine's credential store; the function says so at the end of a run that deploys one. Design: [AI MCP Servers](../ai/mcp-servers.md).

## [Get-AiArtifactManifest](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Get-AiArtifactManifest.ps1)

- **Description:** Reads an AI artifact manifest, the file a manifest source (`AiArtifacts.Manifests`) names: UTF-8, tab-separated, one header row (`name`, `kind`, `scope`, `source`, `ref`, `path`, `install`), `#` comment lines and blank lines ignored. `kind` is `skills`, `mods`, `rules`, `prompts` or `agents`; `scope` is `*`, profile names separated by commas, or one `repo:<name>`; `source` is `https://github.com/<owner>/<repo>` (a trailing `.git` is dropped); `ref` a full 40-character commit SHA; `path` the item's folder inside the source (never leaving it); `install` is `clone`, optionally followed by `rename=<new-name>` and/or `strip-invocation-guard` (space or comma separated). A row that breaks the format, or a second row installing the same name for the same scope, is left out with a problem naming its line, so one bad row never hides the rest. Returns `@{ Path; Rows; Problems }`, each row `@{ Line; Name; LinkName; Kind; Scope; Repository; Source; Owner; Repo; Ref; Path; Rename; StripInvocationGuard }` (`LinkName` the installed name, `Repository` the name of a `repo:` scope). Fetches and writes nothing. Used by [Get-AiArtifactRoster](#get-aiartifactroster) and [Sync-AiManifestCache](#sync-aimanifestcache).
- **Parameters:** -Path
- **Usage:** `(Get-AiArtifactManifest -Path "C:\Users\You\Development\GitHub\MySkills\third-party\manifest.tsv").Rows`

## [Get-AiArtifactPlan](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Get-AiArtifactPlan.ps1)

- **Description:** Builds the deployment plan that [Deploy-AiArtifacts](#deploy-aiartifacts) carries out and [List-AiArtifacts](#list-aiartifacts) `-ListDiscrepancies` checks, by joining the harness definitions of the resolved configuration with the roster of each kind ([Get-AiArtifactRoster](#get-aiartifactroster)). A destination two harnesses name is planned once, for the first (a second definition that differs in kind, placement or files is reported). `Each` and `Copy` destinations get one entry per item - the item folder when `Files` holds `.`, else the first file of the list the item has, named `<item>` plus that file's extension (`claude.md` as `<item>.md`, `copilot.agent.md` as `<item>.agent.md`); an item with none of them is left out. A `File` destination gets the item `AiArtifacts.Use` names for its kind (with an AI profile active, its `Rules` item), if it has one of the files. When `claude-code` is deployed, the roster's repository-scoped skills (manifest rows scoped `repo:<name>`) get one destination per repository, `<repository>\.claude\skills`, harness `repo:<name>`, hook `git-exclude`, with the repository's folder in `Repository`; the repository is found by name in `RepositoryGroups` through [Resolve-RepositoryTargets](git.md#resolve-repositorytargets) (an unknown one is a warning, one not cloned a note). Returns `@{ Destinations; Warnings; Notes }`: each destination is `@{ Harness; Kind; Placement; Hooks; Path; WSLPath; Items }` and each item `@{ Kind; Name; Source; Target; WSLTarget }`; `Warnings` holds problems (an unknown harness, an incomplete destination, a duplicate item, a `Use` entry naming no item, the roster's manifest problems), `Notes` things left out on purpose. Writes nothing.
- **Parameters:** -Kind, -Config
- **Usage:** `Get-AiArtifactPlan`, `Get-AiArtifactPlan -Kind Rules`, `(Get-AiArtifactPlan).Destinations | ForEach-Object { "$($_.Path): $($_.Items.Count)" }`

## [Get-AiArtifactRoster](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Get-AiArtifactRoster.ps1)

- **Description:** Enumerates the AI artifacts of one kind from every source, flattened by item name - the single reading every AI artifact function shares, so what is listed is exactly what is deployed. Sources, in precedence order (the first wins a name two carry): `own`; every `AiArtifacts.Checkouts` entry in name order (the items under the kind's folders of a local repository, linked straight from it); `winux` (the product skills); `example`; every `AiArtifacts.Sources` entry in name order; every `AiArtifacts.Manifests` entry in name order (the rows of its manifest for this kind, read by [Get-AiArtifactManifest](#get-aiartifactmanifest), whose scope is `*` or the active AI profile, from the manifest cache `<CacheRoot>\<owner>\<repo>\<ref>\<path>`, or the derived copy `<ref>.derived\<link-name>` of a `strip-invocation-guard` or `rename=` row, under their `rename=` name, their source being the lowercased upstream owner of the row's `source`, so `kind/<owner>/name` matches that upstream only; a checkout item's source is the checkout source's name). Any other folder under the kind is not read. An item is a folder: a skill holds `SKILL.md`, a mod `.claude-plugin\plugin.json`, a rules, prompt or agent item at least one file not starting with a dot. The excludes apply (`AiArtifacts.Exclude` and the profile's; `kind/name` for every source, `kind/source/name` for one, wildcards allowed), the profile's `Include` entries limit a kind they name, names compare case-insensitively. Returns `@{ Root; Kind; Items; Duplicates; Repo; Problems }`: `Items` an ordered map of name to `@{ Name; Path; Source; SourceKind; Kind; Manifest }` (`Manifest` the manifest source's name of a manifest item) (`SourceKind` one of `own`, `checkout`, `product`, `example`, `vendored`, `manifest`), `Duplicates` the losing entries with the source they lost to, `Repo` the `repo:<name>` manifest skills for [Get-AiArtifactPlan](#get-aiartifactplan), `Problems` the manifest problems and the rows whose ref is not in the cache yet. A missing root, kind folder, checkout or manifest yields fewer items.
- **Parameters:** -Kind, -Config
- **Usage:** `(Get-AiArtifactRoster -Kind Skills).Items.Count`, `(Get-AiArtifactRoster -Kind Rules).Items['CoreAiRules'].Source`

## [Get-AiSkillDescription](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Get-AiSkillDescription.ps1)

Returns an empty string when the file has no frontmatter or no description. Used by [Update-AiArtifacts](#update-aiartifacts) for the item table in `UPSTREAM.md` and by [List-AiArtifacts](#list-aiartifacts) for each item's summary.
- **Parameters:** -SkillFile
- **Usage:** `Get-AiSkillDescription -SkillFile "C:\Repo\AI\Skills\mattpocock\grill-me\SKILL.md"`

## [Get-AiSkillManifest](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Get-AiSkillManifest.ps1)

- **Description:** Reads an `UPSTREAM.md` manifest of a vendored source folder (`<Root>\<Kind>\<source>\UPSTREAM.md`, written by [Update-AiArtifacts](#update-aiartifacts)) and returns a hashtable with `Commit` (the pinned upstream sha) and `Skills` (every vendored item name, whatever its kind). A missing manifest yields an empty commit and no items. `Update-AiArtifacts` uses the names to know which folders it owns and the commit for `-Check`.

## [Initialize-AiProfile](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Initialize-AiProfile.ps1)

- **Description:** Walks the one-time sign-ins of this machine's AI profile ([Resolve-AiProfile](#resolve-aiprofile)), interactively, once per machine after Bootstrap or as its opt-in step `AiProfileInit` (`BootstrapConfig.Steps.AiProfileInit`, off by default; it runs right after `AiMcpServers`, and with it off Bootstrap only names this function when a profile is active); it never asks for, reads, prints or stores a secret. 1. Claude Code: compares the logged-in Plan (`oauthAccount` of `~\.claude.json`) with the profile's Plan and, when they differ, says which Plan (name and org UUID) to sign in to with `claude`, `/logout`, `/login`, never `claude setup-token` or `CLAUDE_CODE_OAUTH_TOKEN`, then waits for Enter and checks again. 2. GitHub CLI: `gh auth status`, and `gh auth login` (interactive) when it is not signed in. 3. The profile's OAuth MCP servers (`AiMcpServers.Servers` filtered by its `McpServers`: a `Url` without `BearerTokenEnvVar` or an `Authorization` header) are listed with their sign-in, `/mcp` in Claude Code and `codex mcp login <name>`. 4. Every name in the profile's `EnvVars` is checked for presence in the process, user or machine environment (never its value), and a missing one is listed with the `[Environment]::SetEnvironmentVariable(...)` command to type yourself. 5. [Test-AiProfile](#test-aiprofile) runs and leaves its exit code in `$LASTEXITCODE`. With no AI profile configured it only says so.
- **Parameters:** -Command, -GhCommand
- **Usage:** `Initialize-AiProfile`

## [List-AiArtifacts](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/List-AiArtifacts.ps1)

- **Description:** The catalog counterpart to [Deploy-AiArtifacts](#deploy-aiartifacts): lists the AI artifacts the repository carries, grouped by kind and then source, each with the `description:` of its frontmatter (`SKILL.md`, the first Markdown file of a rules, prompt or agent item) or of a mod's `plugin.json`. The roster comes from disk exactly as `Deploy-AiArtifacts` reads it ([Get-AiArtifactRoster](#get-aiartifactroster): `own` first, then the checkout, product, example, vendored and manifest sources, the excludes applied), so a vendored refresh shows up at once. Each group header names the source and, when it differs from the name, its kind (`checkout`, `product`, `vendored`, `manifest`); a repository-scoped manifest skill is listed in a group of its own (`manifest, repo:<name>`). `-Kind` limits the kinds, `-Source` picks sources by number or name and `-Name` filters item names with wildcards, case-insensitively; an empty `-Source @()` or `-Name @()` opens a menu. `-ListDiscrepancies` compares the roster with what is deployed into the Windows destinations of the harnesses `AiArtifacts.Deploy` names ([Get-AiArtifactPlan](#get-aiartifactplan)), reporting an item that is not deployed, an entry that shadows one with a real file or points elsewhere, a dangling or orphaned link into the artifacts root, the manifest cache or a checkout source, managed settings that are a link or differ from the copy [ConvertTo-AiManagedSettings](#convertto-aimanagedsettings) renders, an item name two sources carry, and the plan's warnings; WSL twins are not read (re-run `Deploy-AiArtifacts` to reconcile them). `-Quiet` suppresses the all-clear banner. The catalog is drawn with the helpers `List-Functions` uses - a [Create-CenteredBorder](helper.md#create-centeredborder) header per kind and source, [Show-FunctionDetails](helper.md#show-functiondetails) per entry - and everything it emits on its own account goes through the Logging module.
- **Parameters:** -Kind, -Source, -Name, -ListDiscrepancies, -Quiet
- **Usage:** `List-AiArtifacts`, `List-AiArtifacts -Kind Skills -Source own`, `List-AiArtifacts -Name "*review*"`, `List-AiArtifacts -ListDiscrepancies`

## [Resolve-AiArtifactsConfig](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Resolve-AiArtifactsConfig.ps1)

## [Resolve-AiProfile](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Resolve-AiProfile.ps1)

- **Description:** Resolves the AI profile this machine runs from `AiProfiles`, the one resolver every AI function uses: the `WINUX_AI_PROFILE` environment variable (an override naming no configured profile is warned about and ignored), then this host's `Hosts` entry (case-insensitive), then `Default`. Each profile is normalised: `Plans` from `Plan` (one `@{ Name; OrgUuid }` or an array; a non-UUID is warned about and kept out of `Plans` but recorded in the profile's `PlanErrors`, so the managed settings are not rendered without the pin, UUIDs lowercased, whitespace in a name turned into `-`), `Deploy`, `McpServers` and `Marketplaces` `$null` when left out (all) and an array otherwise (`@()`: none), `Include` and `Exclude` lowercased, and the repository patterns `Owns`, `Autonomous`, `Policies`, `MergeWithoutChecks` and `Shared` normalised the way the ownership guard normalises an `origin` remote (lowercase, no scheme, no user, no `.git`). `Policies` comes back ordered from most to least trust (`autonomous`, `branch`, `draft`, `readonly`, `blocked`), with `Autonomous` merged into its `autonomous` patterns; a level outside that set is warned about and skipped, and `DefaultPolicy` is `branch` when unset and `readonly`, with a warning, when it is not a level. `DefaultOwner` falls back to `Default`. Returns `@{ Enabled; Name; Source; HostName; Profile; Profiles; Shared; DefaultOwner; Warnings }`, `Source` being `override`, `hostname` or `default`. Reads configuration only; used by [Resolve-AiArtifactsConfig](#resolve-aiartifactsconfig), [Deploy-AiMcpServers](#deploy-aimcpservers), [Deploy-AiMarketplaces](#deploy-aimarketplaces), [Test-AiProfile](#test-aiprofile) and [Initialize-AiProfile](#initialize-aiprofile).

## [Sync-AiManifestCache](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Sync-AiManifestCache.ps1)

- **Description:** Clones the pinned refs the manifest sources need into the manifest cache, outside every repository: each `source` + `ref` of a row that applies here (scope `*` or the active AI profile, and every `repo:<name>` row; with profiles off `*` and `repo:` rows only) is fetched once into `<CacheRoot>\<owner>\<repo>\<ref>\` (`%LOCALAPPDATA%\WinuX\ai-manifests`): only the pinned commit, by a shallow fetch of its id (`git fetch --depth 1 <source> <ref>`, then `git checkout --detach FETCH_HEAD`), the full `git clone --no-checkout` and `git checkout --detach <ref>` only when the server refuses that; each fetch is announced as it starts (`Fetching manifest ref => [<source>@<ref7>]`) and runs with git's credential prompts off (`GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, put back afterwards), so a private or renamed upstream fails at once instead of waiting; in `<ref>.partial` first and renamed only once the checkout succeeded, so a broken fetch never looks complete; a ref already there is never fetched again. A `strip-invocation-guard` or `rename=` row gets a derived copy of its item in `<ref>.derived\<link-name>\` (the `rename=` name, else the row's name), made once: `strip-invocation-guard` removes the `disable-model-invocation` line from the frontmatter of its `SKILL.md`, `rename=` rewrites the frontmatter `name:` to the new name (Claude Code names a skill by its frontmatter, not its folder). `-Check` fetches nothing: it asks each source for its default branch head (`git ls-remote <source> HEAD`) and reports every row whose pinned ref is not that head. `-Source` limits it to some manifest sources. Returns `@{ Fetched; Present; Failed; Behind; Problems }`. Run by [Deploy-AiArtifacts](#deploy-aiartifacts) before it plans and by [Update-AiArtifacts](#update-aiartifacts).
- **Parameters:** -Config, -Source, -Check
- **Usage:** `Sync-AiManifestCache`, `(Sync-AiManifestCache -Check).Behind`

## [Update-AiArtifacts](https://github.com/IvanPavlak/WinuX/blob/master/Windows/PowerShell/Modules/AI/Functions/Update-AiArtifacts.ps1)

- **Description:** Vendors AI artifacts from the upstream repositories in `AiArtifacts.Sources` into `<Root>\<Kind>\<source>\`, pinned. Per source it resolves `Ref` to an exact commit through the GitHub API and downloads that commit's archive once, then, for every kind the entry names (`Skills`, `Mods`, `Rules`, `Prompts`, `Agents` = upstream folders, `.` for the repository root; no kind key: `Skills = @("skills")`), copies the items found: skills are the folders holding `SKILL.md` (the category level dropped), mods a folder holding `.claude-plugin\plugin.json` or each such subfolder (named by its `plugin.json` `name`), rules, prompts and agents every subfolder plus every top-level `NAME.md` (not `README`, `CHANGELOG` or `LICENSE`), which becomes item `NAME` holding it as `RULES.md`, `PROMPT.md` or `AGENT.md`. The entry's `Exclude` items are left out, and so are the top-level entries of an item listed in `SkipPaths` (default `.git`, `.github`, `tests`, `design`, `docs`). Writes `UPSTREAM.md` per kind folder (repository, commit, fetch time, folders, exclusions, skipped paths, item table; LF, the format [Get-AiSkillManifest](#get-aiskillmanifest) reads) and the upstream license. Only items the previous manifest lists are replaced, so hand-made folders survive; a network failure leaves the vendored copy untouched. `-Check` compares each pinned commit with the upstream head and changes nothing. Private repositories work with a GitHub token (`GITHUB_TOKEN`, else `GH_TOKEN`, else `gh auth token`): both requests then authenticate and the archive comes from the API's zipball endpoint; the token goes only to `api.github.com` and is never logged. Manifest sources (`AiArtifacts.Manifests`) are not vendored: their missing pinned refs are cloned into the manifest cache ([Sync-AiManifestCache](#sync-aimanifestcache)), and with `-Check` every row whose upstream default branch has moved past its pin is reported and nothing is fetched; `-Source` may name manifest sources too, and an empty `Sources` with manifest sources is not "nothing to vendor". Not a Bootstrap step: the vendored tree is committed, and [Deploy-AiArtifacts](#deploy-aiartifacts) links it (and clones missing manifest refs itself).
- **Parameters:** -Source, -Check
- **Usage:** `Update-AiArtifacts`, `Update-AiArtifacts -Source mattpocock`, `Update-AiArtifacts -Check`, `$env:GITHUB_TOKEN = "<token>"; Update-AiArtifacts -Source my-private-source`

**See also:** [Get-AiSkillManifest](#get-aiskillmanifest), [Get-AiSkillDescription](#get-aiskilldescription), [AI Artifacts - Vendoring](../ai/artifacts.md#vendoring)
